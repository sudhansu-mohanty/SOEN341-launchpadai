# Team Process - Sprint 1

## Workflow

The GitHub repository was created by Sudhansu. Responsibilities are distributed as follows:

* Sudhansu: Full Stack
* Fatma: Backend
* Abidi: Technical Documentation + Backend
* Othmane: Full Stack
* Ahcene: Full Stack

The team uses GitHub Issues and the project board to assign tasks and track progress. Full-stack members can help with frontend and backend tasks as needed.

## Branching Strategy

The team uses the main branch for the main project code. Separate branches are used for individual tasks, allowing everyone to work on different parts of the project and help with other tasks when needed.

## Pull Request Process

When a task is completed, a pull request is created and linked to its GitHub Issue. Changes are reviewed before being merged into main.

## Code Review Process

Code is reviewed to check for errors, readability, and whether it meets the requirements. Any necessary changes are made before merging.

## Definition of Ready (DoR)

A task is ready when its requirements are clear, its priority is set, and it is assigned.

## Definition of Done (DoD)

A task is done when it meets its requirements, has been tested and reviewed, and is merged into main. The related GitHub Issue is then updated and closed.
